# 🚀 Complete Deployment Guide: Render Backend + Vercel Frontend

## ⚡ Part 1: Backend Deployment to Render

### Step 1.1: Create Render Account & Connect GitHub
1. Go to [render.com](https://render.com)
2. Sign up with GitHub account
3. Authorize Render to access your repositories

### Step 1.2: Create Backend Service on Render

1. **Dashboard → New+ → Web Service**
2. **Connect Repository**
   - Select your `Projects-Matchmaker` repository
   - Click "Connect"

3. **Configure the Web Service**
   - **Name**: `projects-matchmaker-api` (or your choice)
   - **Environment**: `Node`
   - **Region**: Choose closest to your users (e.g., `Ohio` for US, `Frankfurt` for EU)
   - **Branch**: `main` (or your default branch)
   - **Build Command**: 
     ```bash
     cd Backend && npm install
     ```
   - **Start Command**: 
     ```bash
     cd Backend && npm start
     ```
   - **Instance Type**: `Starter` ($7/month) for development, `Standard` ($12/month) for production

### Step 1.3: Add Environment Variables

In the Render dashboard, go to **Environment** tab and add these variables:

```
GITHUB_CLIENT_ID=your_github_client_id
GITHUB_CLIENT_SECRET=your_github_client_secret
GITHUB_CALLBACK_URL=https://your-render-backend-url.onrender.com/auth/github/callback
SUPABASE_URL=your_supabase_url
SUPABASE_ANON_KEY=your_supabase_key
FRONTEND_URL=https://your-vercel-frontend-url.vercel.app
JWT_SECRET=your_jwt_secret_key
NODE_ENV=production
PORT=3000
```

**Important**: Get these from:
- GitHub OAuth: GitHub Settings → Developer settings → OAuth Apps
- Supabase: Project Settings → API Keys

### Step 1.4: Configure GitHub Callback URL

After Render creates your service, you'll get a URL like `https://xxx.onrender.com`

Update in GitHub OAuth app settings:
- Authorization callback URL: `https://your-render-backend-url.onrender.com/auth/github/callback`

### Step 1.5: Deploy
- Click **Deploy**
- Render will build and deploy your backend
- Wait for "Live" status (2-5 minutes)
- Your API URL: `https://your-render-backend-url.onrender.com`

## ⚡ Part 2: Frontend Deployment to Vercel

### Step 2.1: Create Vercel Account
1. Go to [vercel.com](https://vercel.com)
2. Sign up with GitHub

### Step 2.2: Import Project to Vercel

1. **Dashboard → New Project**
2. **Import Git Repository**
   - Select your `Projects-Matchmaker` repo
   - Click Import

### Step 2.3: Configure Build Settings

1. **PROJECT SETTINGS**
   - **Framework Preset**: `Vite`
   - **Root Directory**: `./frontend`
   - **Build Command**: `npm run build`
   - **Output Directory**: `dist`
   - **Install Command**: `npm install`

### Step 2.4: Add Environment Variables

In **Settings → Environment Variables**, add:

```
VITE_API_URL=https://your-render-backend-url.onrender.com/api
VITE_APP_NAME=Open Source Matchmaker
VITE_ENABLE_API_DISCOVERY=true
```

⚠️ **NOTE**: Frontend vars must start with `VITE_` to be accessible in the browser

### Step 2.5: Deploy
- Click **Deploy**
- Vercel will build and deploy
- Your frontend URL: `https://your-project.vercel.app`

## 🚀 Part 3: Performance Optimization

### 3.1: Backend Performance (Render)

**Create a `.render-buildignore` file in Backend folder:**
```
.git
.gitignore
node_modules
logs/
*.md
```

**Already good in your code:**
- ✅ Helmet for security headers
- ✅ CORS configured
- ✅ Rate limiting enabled
- ✅ Express compression ready

**Additional optimization - Edit Backend/src/app.js:**

Add compression middleware (after helmet):
```javascript
const compression = require('compression');
app.use(compression());
```

**Update Backend/package.json to include compression:**
```json
"dependencies": {
  "compression": "^1.7.4",
  // ... other deps
}
```

**Then run in Backend folder:**
```bash
npm install
```

### 3.2: Frontend Performance (Vercel)

**Create `frontend/vercel.json`:**
```json
{
  "buildCommand": "npm run build",
  "outputDirectory": "dist",
  "env": {
    "NODE_ENV": "production",
    "VITE_PLUGIN_VUE_INSPECT": "false"
  },
  "regions": ["sfo1"],
  "functions": {
    "api/**": {
      "memory": 1024,
      "maxDuration": 60
    }
  }
}
```

**Optimize vite.config.js - Update `frontend/vite.config.js`:**
```javascript
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  build: {
    minify: 'terser',
    terserOptions: {
      compress: {
        drop_console: true
      }
    },
    rollupOptions: {
      output: {
        manualChunks: {
          'react-vendor': ['react', 'react-dom'],
          'router': ['react-router-dom'],
          'query': ['@tanstack/react-query']
        }
      }
    }
  },
  server: {
    middlewareMode: true
  }
})
```

**Optimize API calls - Update `frontend/src/services/apiClient.js`:**
```javascript
import axios from 'axios';

const apiClient = axios.create({
  baseURL: import.meta.env.VITE_API_URL || 'http://localhost:3000/api',
  timeout: 10000,
  headers: {
    'Content-Type': 'application/json'
  }
});

// Add response caching
const cache = new Map();
const CACHE_DURATION = 5 * 60 * 1000; // 5 minutes

apiClient.interceptors.response.use(
  response => {
    if (response.config.method === 'get') {
      cache.set(response.config.url, {
        data: response.data,
        timestamp: Date.now()
      });
    }
    return response;
  },
  error => Promise.reject(error)
);

apiClient.interceptors.request.use(
  config => {
    if (config.method === 'get') {
      const cached = cache.get(config.url);
      if (cached && Date.now() - cached.timestamp < CACHE_DURATION) {
        return Promise.resolve({ data: cached.data, status: 200, config });
      }
    }
    return config;
  }
);

export default apiClient;
```

## 🐛 Troubleshooting

### Backend won't start on Render
- Check environment variables are set correctly
- Check logs: Dashboard → Service → Logs
- Ensure `FRONTEND_URL` matches your Vercel domain

### Frontend can't connect to backend
- Check `VITE_API_URL` includes `/api` suffix
- Check CORS is enabled in backend
- Check GitHub Callback URL matches your Render URL

### Slow performance
- Enable Gzip compression (backend)
- Use Vite's code splitting (frontend)
- Check Render/Vercel metrics for bottlenecks
- Use CDN for static assets

### Rate limiting issues
- Increase limit in Backend/src/app.js if needed
- Implement backend caching
